# Review of the whole repo, 2026-11-17

A one-time review of the stack as it stood at 004247f (driver patches 0003-0007, daemon, app, bar plugin, scripts, BIOS tools),
plus the live machine. Load assumed: one user on one machine, the bar polling all the time, the app open now and then.
Items are numbered so they can be cited ("review item 4"). Status is as of the end of the review.

What was checked and is in good shape:

- Patches 0003-0007 over `base-before-0003.c` reproduce `driver/src` byte for byte. The DKMS source in `/usr/src/uniwill-avell-7.2.15.1`,
  `/etc/systemd/system/avelld.service` and `/usr/local/bin/avelld` match the repo.
- `cargo test`: 52 passing, clippy clean. `app/bin/test`: 13 passing. `node bar-plugin/test/model.test.js`: ok.
- No BIOS tool can write the flash (`bios/backup.sh` calls flashrom with `--read` only). `bios/nvar.py` finds the same NVAR stores and
  entry counts as UEFIExtract.
- D-Bus policy: only root owns `org.avell.Control1`, and every method that changes something calls `authorize()`.
- The app's and the bar's ranges match `config.rs` and `status.rs`; the bar passes fixed words as arguments, so no shell injection.

## Must fix

1. **Status polling keeps the graphics card awake, on battery too** (`daemon/src/status.rs:213`, `bar-plugin/Poller.qml:94`,
   `app/src/backend.cpp:35`). Every GetStatus runs `nvidia-smi` when the card is awake. The bar asks every 3 s for as long as it
   exists; the app every 2 s, also in the background. Game detection does not sample on battery (`engine.rs:222`), so the ~7 W on
   battery of #44 comes from status polling. Fix: one caller of `nvidia-smi` (the engine); GetStatus reports the engine's last sample;
   #44's back-off then lives in one place. Test: a fake probe that counts calls while GetStatus is polled.
2. **thermald replaced the CPU long-term limit of the bundle. Fixed in this review.** Observed: profile performance (80 W / 80 W),
   kernel `constraint_0` 120 W, `constraint_1` 80 W. thermald 2.5.13 (Omarchy enables it on Intel laptops,
   `/usr/share/omarchy/install/hardware/intel/thermald.sh`) ignores `--adaptive` here and runs its default engine. Its debug log shows
   zone `cpu`: passive trip 95 °C on `x86_pkg_temp`, first cooling device `rapl_controller` (PL1 from 120 W down to 60 W in 6 W steps,
   back to 120 W when cool), order taken from `/etc/thermald/thermal-cpu-cdev-order.xml`. The daemon writes the limits only on a
   profile change, a power-source change or a resume. Fix: `install.sh` removes `rapl_controller` from that file, and the pacman hook
   `daemon/dist/avelld-thermald.hook` does it again after thermald updates (the file is not a pacman backup file, so updates overwrite it);
   `uninstall.sh` puts it back byte for byte. Applied by hand on the machine; thermald's `cpu` zone now uses `intel_pstate`,
   `intel_powerclamp` and `Processor`, and `avellctl profile set performance` brought the limit back to 80 W. Left: thermald writes its
   start-up PL1 back whenever it stops ("Restoring RAPL power limits on exit"), so a `systemctl restart thermald` still clobbers the
   limit until the next profile change. Not yet seen: a hot spell (95 °C) with the limit staying at the bundle's value.
3. **35 commits, including the only BIOS backup found, exist only on this laptop's SSD.** `main` is ahead of `origin` on purpose
   (pushing to `main` closes issues). Fix: `git push origin main:backup` (a non-default branch closes nothing), and a copy of
   `evidence/bios/*.bin` off the machine (#19). Keep the repo private: the image holds the machine's serial number.

## Should fix

4. **`nvidia-smi` has no timeout** (`daemon/src/real.rs:56-59`). A hung `nvidia-smi` hangs the engine for good: fans fall back to the
   firmware (safe), but bundles, charger rules and the API stop, and systemd does not restart a live process. Fix:
   `tokio::time::timeout(3 s)` and `kill_on_drop(true)`.
5. **The driver's fan safety net can switch itself off** (`driver/src/uniwill-acpi.c:1746-1764`, `:1913`, patch 0007).
   `uniwill_fan_leave_manual()` sets the mode to automatic before its EC writes; if one fails, the fan tables stay on at the daemon's
   last duty and the watchdog stops. A later mode read adopts the tables as manual (`:1913`) without restarting the watchdog, so a dead
   daemon then leaves the fans at its last duty and the 95/87 °C limits are not enforced (only the dummy zones at 115/120 °C). Fix: in
   that branch set `fan_last_write = jiffies` and `mod_delayed_work()` the watchdog, which then retries the hand-back. Rare (needs an
   EC write error); found by reading, not reproduced.
6. **Three check scripts fight the running daemon** (`driver/checks/fans.sh`, `direct-fan.sh`, `power-profile.sh`). None hands the fans
   over first; avelld takes them back within 2 s (`engine.rs:352-361`). `fans.sh` reports a false FAIL, `direct-fan.sh` never sees the
   watchdog fire, the EXIT trap's `echo 2` is undone, and `power-profile.sh --measure` measures the daemon's limits. Fix: start with
   `avellctl fan set automatic`; for `--measure`, stop avelld and start it again in the trap.
7. **`daemon-fans.sh` cannot run on this boot** (`driver/checks/daemon-fans.sh:8`). Under `set -e` the hwmon loop fails whenever
   `uniwill` is not the last hwmon device (hwmon4 of 0-8 now). `restore()` also never restarts avelld if the clean-stop step fails.
   Fix: `grep -l '^uniwill$' /sys/class/hwmon/hwmon*/name | xargs dirname` (as `cpuload.sh`), and `systemctl start avelld` in `restore()`.
8. **`install.sh` removes the working driver before the new one builds** (`scripts/install.sh:22-30`). A failed build stops the script
   after `dkms remove`; the next boot has no driver for this board. Fix: build a temporary copy with
   `make -C /lib/modules/$(uname -r)/build M=$tmp` first and stop if it fails.
9. **`backup.sh` overwrites an existing BIOS backup** (`bios/backup.sh:29-30`). The name is BIOS version plus date: a setting change
   and a second backup the same day replace the clean image. `BACKUP.md` says it refuses. Fix: refuse when the target exists.
10. **SetFan reports success when it did nothing** (`daemon/src/engine.rs:321`, `:309-312`). No fan control (e.g. the stock driver after
    a failed DKMS build) or a failed `pwm1_enable` write is only logged. The bar shows the Max fan toggle anyway (`Panel.qml:420`).
    Fix: `set_fan` returns an error in both cases; the bar hides the toggle without fan control.
11. **Saving any setting turns off Max fan set with the Fn key** (`daemon/src/engine.rs:183-188`). `set_config` always calls `set_fan`,
    which writes `pwm1_enable = 1` and resets the CPU average. Fix: call `set_fan` only when `fans.mode` changed; `apply()` already
    restarts the curve.
12. **power-profiles-daemon down blanks everything** (`daemon/src/status.rs:241`, `engine.rs:256`, `app/src/backend.cpp:50-53`).
    GetStatus fails as a whole, each tick returns before the fan beat (curve stops, watchdog hands the fans to the firmware, an error
    line every second), and the app keeps showing the last values as live. Seen at the boot of 2026-11-17 13:06:13. Fix: an "unknown"
    profile instead of failing, the fan beat regardless, and the app clears its status on any error.
13. **The interfaces lose or misreport who runs the fans.** Turning Max fan off in the bar always selects the curve
    (`bar-plugin/Poller.qml:61`), dropping a chosen Automatic or fixed speed. With Fn-key Max fan, the bar shows Max but the app
    highlights Curve (`app/src/FansPage.qml:36`). Fix: the bar restores the previous control; the app uses
    `app.st("fans.mode") === "max" ? "max" : app.st("fans.control")`.
14. **The app runs `hyprctl` every second for the window rounding** (`app/src/theme.cpp:50`): 3600 process starts an hour, also when
    minimised. Fix: drop the timer, read it again when the app becomes active.

## Nice to have

15. **The test driver cannot be told from the release driver.** REA `inspect_kernel_module`: the DKMS build
    (`ev_50e315be…`, sha256 `ebd834cb…`, srcversion `E48BF6B4…`, signed) and the test build in
    `~/.cache/uniwill-avell-handover/chgtest/` (`ev_14dd0eb8…`, sha256 `275b452f…`, srcversion `0216C3D6…`, unsigned) both say
    `7.2.15-avell6-local`. The loaded one is the test build. Give test builds their own version suffix.
16. **`bios/nvar.py:65` hangs on an entry whose UTF-16 name has no terminator** (a torn write). Fix: bound the loop by `len(body)`,
    plus a three-case test next to `test-analyze.sh`.
17. **The curve editor's "Add point" can repeat a temperature** (`app/src/CurveEditor.qml:66-69`), e.g. at 110 °C; the daemon then
    refuses the whole save. Return early when the temperature would repeat.
18. **Ctrl-C in `evidence/scripts/cpuload.sh` leaves `openssl` loading every core** for the rest of the run (background jobs ignore
    SIGINT in scripts). Fix: `trap 'kill $P' EXIT`.
19. **Unused code, about 230 lines:** the translation machinery (`app/src/translator.*`, `en.json` is `{}`, its tests and two lines in
    `main.cpp`), `theme.green`, the pwm loop in `scripts/uninstall.sh` (tested as the user, so it never writes), and
    `evidence/scripts/loadtest.py` (hard-coded hwmon numbers that are wrong on this boot; `cpuload.sh` replaces it).
20. **Docs out of date:** `README.md:13` lists bundles, curves, charger rules and game detection as planned; `driver/dkms.conf:4-5`
    describes the old fan interface.

About 15 smaller items were left out (a colour slider jumps 100 → 102, the bar's action error never clears, `mise.toml` lists rustup
twice, uninstall disables nvidia-powerd even if it was on before install, the DKMS version is not looped over on remove).

Not checked: the UI was not run, no on-device check or load test was run (a battery test was in progress), the upstream driver beyond
what the patches add, `docs/research/`, and `evidence/` beyond its scripts.
